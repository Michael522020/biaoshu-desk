# 标枢 · 技术标工作台

> 在浏览器里完成的本地技术标工作台。它把招标资料、要求条目、章节正文、报价试算、检索和 Word / Excel 交付放在同一个项目里，数据留在这台电脑上。

![许可证](https://img.shields.io/badge/license-MIT-2f6fed.svg)
![运行方式](https://img.shields.io/badge/runtime-browser-24312b.svg)
![技术栈](https://img.shields.io/badge/stack-Vite%20%2B%20React-c9862a.svg)

标枢面向投标文件的起草和收口。模型可以按当前章节和资料摘录起草，要求是否已响应、证据是否齐备、正式稿能否导出，都由使用的人在页面上确认。

## 为什么做它

技术标要过的关口，是每一条招标要求都能找到章节，每一句承诺都能回到资料，导出前还能看出哪里没收口。标枢把这件事收成一条可以来回走的流程：先读入资料，再整理要求，再写章节，最后看放行条件。报价试算单独放在一页，方便和技术方案对照，它不代替盖章的商务报价文件。

```mermaid
flowchart LR
    A[导入招标文件与企业资料] --> B[整理并修订招标要求]
    B --> C[把要求分到章节]
    C --> D[本地提纲或模型起草]
    D --> E[核对证据与人工放行]
    E --> F[导出审核稿或正式 Word]
    E -->|退回补写| D
    C --> G[报价试算]
    G --> H[导出矩阵、评分和报价]
```

首页可以打开内置示例「市政桥梁巡检信息化」。示例是虚构数据，用来看评分、报价和检索怎么串起来，不包含真实招标文件或企业资料。

## 已实现功能

| 模块 | 能力 |
| --- | --- |
| 工作台 | 展示当前项目的交付分和等级，以及要求响应、证据完备、章节完成、人工放行四项进度。项目库列出本机已保存的项目，可以打开、新建或删除。 |
| 资料 | 一次导入多份 txt、Markdown、Word（`.docx`）、Excel（`.xlsx` / `.xls`）或可选中文字的 PDF。正文留在项目里，可按份移除。 |
| 要求 | 按语句抽出带约束语气的句子，编成 `R-01` 这样的编号。每条可改原文、标成核心或一般、标成未响应 / 待补证据 / 已响应，并指定负责章节。手工添加的条目在重新整理时会保留。 |
| 正文 | 左侧是章节列表，右侧是标题和正文。可以生成本地提纲，也可以调用已配置的模型按当前章节流式起草。没有资料支撑的资质、案例、数字和承诺会写成「待人工补充」。 |
| 审核 | 列出还没满足的放行条件。审核稿随时可以导出 Word。正式 Word 要等核心要求、证据、正文和人工放行都完成后才能导出。 |
| 报价 | 按名称、单位、数量、单价和税率逐行计算不含税金额、税额和含税合计。金额先按分取整，再汇总。 |
| 检索 | 只在当前项目的要求、章节正文和资料正文里查找，最多返回 30 条。点一条结果会回到对应的项目步骤。检索词不会发给模型。 |
| 模型 | 预置 DeepSeek、硅基流动、本机 Ollama 和 OpenAI，也可以填自定义的 Chat Completions 地址。地址和模型名写入本机；密钥只留在当前浏览器会话。 |

## 数据边界与安全原则

- **默认留在本机。** 项目保存在浏览器的 IndexedDB，库名是 `biaoshu-desk`。应用本身没有账号，也不会把项目上传到自己的服务器。
- **模型只收到当前任务需要的摘录。** 调用模型时，请求里包含系统提示、本章要回应的要求，以及资料正文的一段摘录（最长约 8000 字）。没有点击「调用模型」时，不会向外发送资料。
- **密钥不进项目库。** API 密钥写在 `sessionStorage`，键名是 `biaoshu-session-key`，关掉这个浏览器会话就消失。保存设置时只写入接口地址、模型名和是否本机服务。
- **没有依据就不写成确定事实。** 本地提纲和模型提示都要求：资料里没有的资质、案例、数字和承诺，必须标成「待人工补充」。
- **正式稿由人放行。** 交付分和放行清单是页面上的检查结果。勾选「我已核对要求、证据和正文」之后，正式 Word 才会解锁。

本机地址（`localhost`、`127.0.0.1`、`[::1]`）或标记为本机的配置可以不填密钥，方便直接接 Ollama。

## 快速开始

### 环境

- 一个现代浏览器
- Node.js 20 或更高版本
- npm 10 或更高版本

桌面安装包不在当前版本里。开发、测试和日常使用都通过下面的本地命令完成。

### 取得代码并启动

```bash
git clone https://github.com/Michael522020/biaoshu-desk.git
cd biaoshu-desk
npm install
npm test
npm run dev
```

浏览器打开 http://localhost:5173/ 。

`npm test` 用 Node 自带的测试运行器检查交付分、报价取整、要求抽取和检索。`npm run build` 会把静态站点生成到 `dist/`，该目录已被 Git 忽略。

### 从示例走一遍

1. 在工作台点击「打开示例」。示例项目叫「市政桥梁巡检信息化」，内含一份短资料、三条要求和三个章节。
2. 打开「项目」。步骤是「资料 → 要求 → 正文 → 审核」。
3. 在「要求」里查看 `R-01`、`R-02`、`R-03` 的级别、状态和所属章节，按需要改一改。
4. 在「正文」里选一章，点「生成本地提纲」，或在配置模型后点「调用模型」。
5. 在「审核」里看放行清单。可以先导出审核稿；条件都满足后再导出正式 Word。
6. 打开「报价」，示例里有一行「桥检终端部署」：2 套、单价 1000、税率 6%，含税合计为 2,120.00。
7. 打开「检索」，输入「桥梁」，结果会分别落到要求、章节和资料。

新建空项目从工作台的「新建项目」进入。项目名称可以后改，数据在编辑后约 250 毫秒写入 IndexedDB。删除前会再确认一次，删除后不能从项目库恢复。

## 配置模型服务

打开「模型」，任选一种方式：

| 预设 | 默认地址 | 默认模型 | 密钥 |
| --- | --- | --- | --- |
| 自定义 | 留空，自己填写 | 留空，自己填写 | 非本机地址时需要 |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` | 需要 |
| 硅基流动 | `https://api.siliconflow.cn/v1` | `Qwen/Qwen2.5-32B-Instruct` | 需要 |
| 本机 Ollama | `http://127.0.0.1:11434/v1` | `qwen2.5:7b` | 通常留空 |
| OpenAI | `https://api.openai.com/v1` | `gpt-4.1-mini` | 需要 |

填好后点「保存地址和模型名」。应用会请求 `{地址}/chat/completions`；如果地址本身已经以 `/chat/completions` 结尾，则不再追加。正文生成使用流式输出，温度为 0.2。模型没有返回正文时，页面会提示失败，已写在章节里的内容不会被空结果覆盖。

本机 Ollama 需要先在这台电脑上启动服务，并已拉取对应模型。换一个自定义地址后，预设会回到「自定义」。

## 交付分与正式稿

有要求或章节之后才开始计分。四项加权如下：

| 项目 | 权重 | 怎么算 |
| --- | --- | --- |
| 要求响应 | 40% | 已响应条数 / 要求总数 |
| 证据完备 | 25% | （要求总数 − 待补证据条数） / 要求总数 |
| 章节完成 | 25% | 已有正文的章节 / 章节总数 |
| 人工放行 | 10% | 审核页勾选确认后记满分，否则记 0 |

综合分四舍五入。90 分及以上为 A，75 分及以上为 B，60 分及以上为 C，其余为 D。还没有任何要求和章节时，分数显示为 0，等级为「—」。

正式 Word 在下面四项都消失后才能导出：

- 还有核心要求没有标成已响应
- 还有条目处于「待补证据」
- 没有章节，或有章节正文是空的
- 还没有在审核页勾选人工放行

审核稿不受这四项限制。Excel 工作簿随时可以导出，里面有三张表：「要求矩阵」「交付评分」「报价」。

## 要求是怎么抽出来的

「整理成要求」按行扫描已导入资料。行首的编号会被去掉。剩下的文字要同时满足：

- 长度在 8 到 160 个字之间
- 含有约束语气，例如「必须」「不得」「应当」「应该」「需要」「应」「提供」「支持」「具备」「不少于」「负责」

含「必须」或「不得」的句子标为「核心」，其余标为「一般」。新抽出的条目状态是「未响应」，来源记为文件名。一次最多保留 60 条。重新整理时，标记为手工添加的条目会接在自动结果后面，然后统一重编号。

## 当前范围

这一版把技术标的资料、要求、正文、审核、报价试算和导出连在一起。下面这些还不在范围内：

- 扫描件 OCR。PDF 只抽取已经可选中的文字。
- 企业 Word 模板、页眉页脚和固定锚点映射。导出的是按章节标题和正文生成的 `.docx`。
- 富文本编辑、批注线程和章节历史回退。
- 电子签章。
- 网页检索，以及把检索结果写进标书。
- 云端账号、云同步和多人同时编辑。
- Windows 安装包或便携版。

报价页只做数量、单价和税率的试算，用来和技术方案对照。它不生成盖章用的商务标。

## 项目结构

```text
src/main.jsx           应用外壳：导航、项目读写、新建与删除
src/ui/                工作台、项目四步、报价、检索、模型页
src/lib/score.js       交付分与正式稿放行条件

src/lib/model.js       预设、本地提纲、流式起草

src/lib/exporters.js   Word 与 Excel 导出
src/lib/money.js       报价按分取整
src/lib/search.js      当前项目内检索
src/lib/vault.js       IndexedDB 项目库与模型设置
src/lib/sample.js      桥梁巡检示例
tests/desk.test.mjs    评分、报价、抽取和检索测试
```
